AUDIT SCOPE
- Reviewed make_tracks.py and tools/make_tracks.py scripture ingestion path.

ROOT CAUSE
- The scripture extractor in make_tracks.py contained literal backspace characters where regex word-boundary tokens were intended.
- Because of that, newly added references in MP3 comments/custom tags/lyric text could fail to match.
- Existing older scripture references mostly survived because they were already present in track-metadata.json or preserved in tracks.json.
- The app rendering layer was not the primary failure; the data was missing before the UI received it.

REPAIR COMPLETED
- Replaced the broken regex boundary characters with proper regex word boundaries.
- Expanded scripture parsing to support clean reference normalization such as Genesis 9:12-17, Matthew 17:20, Mark 10:8-9, and 1 Corinthians 13:4-7.
- Added support for multiple metadata spellings: scripture_references, scriptureReferences, scripture_refs, scripture, scriptures, bible_references, bibleReferences, bible_refs, bible, reference, and references.
- Added MP3 custom-tag support for TXXX fields containing scripture/bible/reference/verse text.
- Added broader COMM/comment capture so scripture references stored in comments can be picked up.
- Added preserved-track reconciliation so app-only/no-audio packages can still apply track-metadata.json scripture corrections without wiping tracks.json.
- Mirrored the repaired generator to tools/make_tracks.py.
